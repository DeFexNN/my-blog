Hashinator reverse

challenge_final — Writeup

Analysis

The binary reads input from stdin and requires at least 15 characters.
For an input of length N, it prints N+1 hexadecimal hashes.

Example:

This indicates the program exposes incremental hash states:

So each line corresponds to the hash after processing another byte.

Vulnerability

The binary leaks internal hash states, turning it into a hashing oracle.

Instead of reversing the algorithm, we can reconstruct the flag by matching each prefix hash.

Important detail:

Therefore, when brute-forcing character pos, compare:

(not hash[pos]).

Attack Strategy

  1. Assume flag format ENO{...}.
  2. Build a candidate string of the correct length.
  3. Replace one character at a time.
  4. Run the binary.
  5. Match the hash at pos+1.
  6. Lock the correct character and continue.

No need to reverse the hash function.

Solver

Root Cause

The program exposes intermediate hash states instead of validating only the final digest.

This allows reconstruction of the secret sequentially without reversing the algorithm.
